Week 1 (Feb 9-15): Foundation & Setup
Set up development environment with Node.js, Electron, and React scaffolding. Initialize GitHub repository structure with folders for /src, /scanner-modules, /llm-integration, /ui-components, and /tests. Configure Kali Linux VM with Nmap and ensure Docker is operational for hosting Mutillidae locally. Create .env template for Gemini API key management. Draft initial README with project description and setup instructions. Begin literature review focusing on purple team methodologies, automated vulnerability assessment, and LLM applications in cybersecurity.

Week 2 (Feb 16-22): Literature Review & Pipeline Design
Complete literature review deliverable (due March 6) by surveying 20-30 peer-reviewed sources on vulnerability scanning automation, OWASP classification systems, and LLM prompt engineering for security contexts. Document findings in structured notes. Design the scanning pipeline architecture: define how Nmap XML outputs will be parsed, what JSON schema will store normalized vulnerability data, and how the pipeline orchestrator will queue scanning tasks. Create flowchart showing data flow from target input → Nmap execution → XML parsing → JSON normalization → storage.

Week 3 (Feb 23-Mar 1): Core Pipeline Implementation
Build the Nmap orchestration module in Node.js that accepts target URLs, validates them against an allowlist, executes Nmap with appropriate flags (-sV -sC --script vuln), and captures XML output. Implement XML-to-JSON parser that extracts key fields: target host, open ports, service versions, detected vulnerabilities with CVE references, and script output. Store results in structured JSON files with timestamp and target metadata. Add error handling for failed scans and logging for audit trails.

Week 4 (Mar 2-8): Electron UI Foundation
Scaffold Electron application with React frontend. Create main window with three primary views: Target Configuration (input field with allowlist validation), Scan Control (start/stop buttons with progress indicators), and Results Dashboard (table view of discovered vulnerabilities). Implement IPC communication between Electron main process and renderer for triggering scans and receiving results. Add basic styling with a dark theme suitable for security tooling. Ensure cross-platform compatibility (Windows/Linux).

Week 5 (Mar 9-15): LLM Integration - Part 1
Implement Gemini API integration module that reads JSON scan results and constructs structured prompts. Design prompt template: "Given the following vulnerability scan output [JSON data], provide: 1) A concise vulnerability statement in plain English, 2) Affected endpoints/paths, 3) Severity rating with justification, 4) Specific remediation steps." Handle API authentication via .env file, implement rate limiting to avoid quota issues, and add retry logic for transient failures. Test with sample Nmap outputs to validate response quality.

Week 6 (Mar 16-22): LLM Integration - Part 2 & OWASP Mapping
Refine LLM prompts based on Week 5 testing to improve remediation specificity. Implement response parsing that extracts the four required datasets (statements, endpoints, severity, fixes) from Gemini's output into structured fields. Build OWASP Top 10 mapping logic: use keyword matching and CVE-to-OWASP lookups to categorize each vulnerability (e.g., SQL injection → A03:2021-Injection). Generate coverage summary showing which OWASP categories were found and which remain untested. Display this in the UI as a coverage matrix.

Week 7 (Mar 23-29): Report Generation & Testing Setup
Create PDF/HTML report generator that combines scan metadata, vulnerability findings with LLM-enhanced descriptions, OWASP categorization, and remediation guidance into a professional security report. Add export functionality to the Electron UI. Set up testing infrastructure: deploy Mutillidae in Docker container, verify testphp.vulnweb.com accessibility, document known vulnerabilities in these targets as ground-truth for evaluation. Create test cases for SQL injection, XSS, directory traversal, and authentication bypass scenarios.

Week 8 (Mar 30-Apr 5): Baseline Testing & Evaluation Framework
Execute comprehensive scans against testphp.vulnweb.com and record all findings. Manually review results to establish baseline accuracy metrics: identify true positives (correctly detected vulns), false positives (non-issues flagged), and false negatives (missed vulns). Build evaluation scripts that calculate classification correctness rates. Develop remediation quality rubric with scoring criteria: Completeness (0-3 points), Accuracy (0-3 points), Actionability (0-3 points), Relevance (0-3 points). Apply rubric to sample LLM outputs and document scores.

Week 9 (Apr 6-12): Mutillidae Testing & Metrics Collection
Scan Mutillidae instance across multiple vulnerability categories. Test framework's ability to detect OWASP A01 (Broken Access Control), A02 (Cryptographic Failures), A03 (Injection), and other categories present in Mutillidae. Collect quantitative metrics: detection rates per category, average remediation quality scores, processing time per vulnerability, LLM token usage. Compare performance between Gemini API and optional Ollama local model if implemented. Document any edge cases or failure modes encountered during testing.

Week 10 (Apr 13-19): Polish, Documentation & Presentation Prep
Refactor codebase for readability and maintainability. Add comprehensive inline comments and update README with installation steps, usage examples, and architecture diagrams. Create GitHub wiki pages documenting the evaluation methodology, test results with charts, and lessons learned. Begin dissertation write-up focusing on Results & Analysis chapter (present metrics with tables/graphs). Record 15-20 minute screencast demonstrating: target selection, scan execution, LLM processing, report generation, and OWASP coverage visualization. Edit video for clarity and upload to appropriate platform.
